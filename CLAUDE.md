# EnergyTool AI-консультант (Hack&Change 2026, трек МТС)

Прототип ИИ-консультанта для сайта EnergyTool (energytool.mts.ru). Консультант выясняет задачу клиента, подбирает решение МТС для учёта и экономии энергоресурсов и передаёт менеджеру контакты и краткое резюме диалога.

Кейс публикуется 9 ноября 2026. До этого работаем на данных, собранных с сайта. После выхода кейса меняются в первую очередь файлы в `data/` и `prompts/`, а не код.

## Структура

```

  services/*.md      страницы услуг EnergyTool (собираются через Kimi Web)
  shop/              каталог магазина: shop_kb.md, shop_clean.json, shop_raw.json (fetch_shop.py)
  segments.yaml      сегмент клиента → обязательные слоты (этап 3, делает Виталий)

  catalog.py         load_catalog(): единственное место, где знаем, откуда данные
```

## Главные правила

1. **Контракт.** Форматы `respond()`, `/chat`, `/lead` и лида описаны в `docs/contract.md`. Не меняй их в коде, не обновив сначала контракт. Об изменении контракта всегда сообщай отдельно в ответе — это затрагивает всю команду.
2. **Факты о продуктах только в `data/`.** Названия, цены, условия, ограничения продуктов не хардкодятся в коде и промптах. Промпт получает базу знаний из `load_catalog()`.
3. **Промпты только в `prompts/`.** Не пиши длинные тексты промптов строками внутри Python.
4. **Модель только через `agent/llm.py`.** Нигде больше не импортируй SDK провайдера и не указывай название модели.
5. **Агент не выдумывает.** Если правка промпта или логики может привести к тому, что бот назовёт цену, продукт или факт, которого нет в `data/`, — это регрессия.

## Запреты внутри `agent/`

Агент вызывается и из `cli.py`, и из API на сервере, где одновременно идут сотни диалогов. Поэтому в `agent/`:

- **нет `print()` и `input()`.** Агент получает текст и возвращает результат. Ввод-вывод только в `cli.py`. Для отладки — модуль `logging`;
- **нет глобального состояния диалога.** Всё, что агент знает о диалоге, лежит в `state`, который он получает и возвращает;
- **`state` сериализуется в JSON:** только строки, числа, bool, `None`, списки, словари. Никаких объектов, дат, клиентов SDK;
- **агент сам ничего не сохраняет и не отправляет.** Внешние действия (передача лида) возвращаются в `actions`, выполняет их вызывающий код.

Проверка: два диалога, запущенные вперемешку с разными `state`, не путаются.

## LLM

- Провайдер: polza.ai, OpenAI-совместимый API, `base_url = https://polza.ai/api/v1`.
- Ключ и модель задаются в `.env` (`POLZA_AI_API_KEY`, `LLM_MODEL`). Шаблон — `.env.example`.
- Модель выбирается скриптом `parsing/check_models.py` (вызов инструментов + JSON по схеме + скорость). Если у модели есть режим рассуждений, для агента он отключён.
- Извлечение слотов и резюме — через `response_format` с JSON-схемой. Ответ модели всегда проверяется на соответствие схеме; невалидный — не принимается молча.
- Поля, о которых клиент не говорил, остаются `null`. Новое `null` при слиянии слотов не стирает уже известное значение.

## Команды

```bash
source .venv/bin/activate          # окружение, в каждом новом терминале
pip install -r requirements.txt
python cli.py                      # чат с агентом в терминале
python evals/run_evals.py          # прогон тестового стенда
python parsing/fetch_shop.py       # обновить каталог магазина → data/shop/ (из любой папки)
```

Для обновления страниц услуг используй `prompts/parse_energytool_site.md` в Kimi Web и сохрани полученные Markdown-файлы в `data/services/`.

После правок промптов или логики агента прогоняй `evals/run_evals.py` и показывай результат: что стало лучше, что хуже. Правка, которая чинит один тест и ломает другие, — не улучшение.

## Безопасность и данные

- `.env`, `.venv/`, `leads/` — в `.gitignore`. Ключи никогда не попадают в код, логи и коммиты.
- В тестах и примерах только вымышленные имена и телефоны.
- Сбор контактов в диалоге — только после согласия на обработку персональных данных (152-ФЗ). Без `consent_pd: true` лид не создаётся.
- `parsing/fetch_shop.py` обращается к продакшен-сайту МТС: запускать вручную и по одному разу, не в цикле и не из тестов. Агент и демо работают с локальными файлами в `data/`, а не с сайтом.

## Как работать со мной

- Отвечай по-русски.
- Объясняй, что и почему меняешь, а не только что сделал: код должен быть понятен без тебя.
- Если видишь ошибку в моём решении или более простой путь — скажи прямо, до того как начнёшь делать.
- Делай небольшие изменения, которые легко проверить и откатить. Перед крупной правкой предложи сделать коммит.
- Не добавляй фреймворки и зависимости (LangChain и т. п.) без обсуждения.
