# EnergyTool AI-консультант (Hack&Change 2026, трек МТС)

Прототип ИИ-консультанта EnergyTool. Консультант выясняет задачу клиента, подбирает решение МТС для учёта и экономии энергоресурсов и формирует заявку с контактами и кратким резюме диалога.

После первого чекпоинта используем только официальную базу знаний с Google Drive. Выгрузки сайта EnergyTool больше не являются источником данных. Интерфейс одобрен и не требует визуальных изменений.

## Команда и зоны

- **Агент** (`agent/`, `prompts/`, `evals/`) — Елеазар
- **API** (FastAPI, хранение сессий, Telegram-бот менеджеру, Docker) — Миша
- **Фронтенд** (виджет чата, форма контактов, макет сайта) — Женя
- **Продукт** (сценарий диалога, сегменты и слоты, тестовые клиенты, формат лида, презентация) — Виталий

Не правь чужую зону без явной просьбы. Если задача требует изменений там — скажи, что и почему нужно поменять.

## Структура

```
docs/contract.md     стыки между агентом, API и фронтом. Источник правды по форматам
docs/agent_plan.md   этапы разработки агента и их статусы
data/
  knowledge-base/    официальная база: 00-reference/, 10-energy/, 20-products/
  segments.yaml      сегмент клиента → обязательные слоты (этап 3, делает Виталий)
prompts/             тексты промптов, по файлу на промпт
agent/
  llm.py             call_llm(): единственное место, где знаем про провайдера LLM
  catalog.py         чтение официальной базы и полнотекстовый поиск по ней
  state.py           слоты и этапы диалога
  agent.py           respond(message, state) -> AgentResult
parsing/             проверка моделей; старые скрипты сайта не используются агентом
evals/               тестовые клиенты и прогон стенда
cli.py               чат с агентом в терминале
leads/               лиды из терминальной версии (не коммитится)
```

## Главные правила

1. **Контракт.** Форматы `respond()`, `/chat`, `/lead` и лида описаны в `docs/contract.md`. Не меняй их в коде, не обновив сначала контракт. Об изменении контракта всегда сообщай отдельно в ответе — это затрагивает всю команду.
2. **Факты о продуктах только в `data/knowledge-base/`.** Названия, цены, условия, ограничения продуктов не хардкодятся в коде и промптах. Промпт получает найденные фрагменты через `agent/catalog.py`.
3. **Промпты только в `prompts/`.** Не пиши длинные тексты промптов строками внутри Python.
4. **Модель только через `agent/llm.py`.** Нигде больше не импортируй SDK провайдера и не указывай название модели.
5. **Агент не выдумывает.** Если правка промпта или логики может привести к тому, что бот назовёт цену, продукт или факт, которого нет в официальной базе, — это регрессия.
6. **Скорость.** Целевое время интерактивного ответа — менее 8 секунд. Не добавляй лишние вызовы LLM без измерения последствий.

## Запреты внутри `agent/`

Агент вызывается и из `cli.py`, и из API на сервере, где одновременно идут сотни диалогов. Поэтому в `agent/`:

- **нет `print()` и `input()`.** Агент получает текст и возвращает результат. Ввод-вывод только в `cli.py` и отдельном `solution.py`. Для отладки — модуль `logging`;
- **нет глобального состояния диалога.** Всё, что агент знает о диалоге, лежит в `state`, который он получает и возвращает;
- **`state` сериализуется в JSON:** только строки, числа, bool, `None`, списки, словари. Никаких объектов, дат, клиентов SDK;
- **агент сам ничего не сохраняет и не отправляет.** Внешние действия возвращаются вызывающему коду.

Проверка: два диалога, запущенные вперемешку с разными `state`, не путаются.

## LLM

- Локально: polza.ai, OpenAI-совместимый API, модель `qwen/qwen3.8-27b` в `.env`.
- Локальные ключ и модель задаются в `.env` (`POLZA_AI_API_KEY`, `LLM_MODEL`). Шаблон — `.env.example`.
- На платформе адрес, ключ и модель приходят через `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` или документированные альтернативы. Свой ключ не нужен.
- Если у модели есть режим рассуждений, для агента он отключён.
- Извлечение слотов и резюме — через JSON-схему, если это поддерживает текущий API. Ответ модели всегда проверяется; невалидный не принимается молча.
- Поля, о которых клиент не говорил, остаются `null`. Новое `null` при слиянии слотов не стирает уже известное значение.

## Команды

```bash
source .venv/bin/activate          # окружение, в каждом новом терминале
pip install -r requirements.txt
python cli.py                      # чат с агентом в терминале
python evals/run_evals.py          # прогон тестового стенда, когда он будет добавлен
```

После правок промптов или логики агента прогоняй локальные проверки и показывай результат: что стало лучше, что хуже. Правка, которая чинит один тест и ломает другие, — не улучшение.

## Безопасность и данные

- `.env`, `.venv/`, `leads/` — в `.gitignore`. Ключи никогда не попадают в код, логи и коммиты.
- В тестах и примерах только вымышленные имена и телефоны.
- Сбор контактов в диалоге — только после согласия на обработку персональных данных (152-ФЗ). Без `consent_pd: true` лид не создаётся.
- Агент и демо работают с локальными файлами официальной базы, а не с сайтом.
- Материалы кейса не публиковать в открытых хранилищах. Не включать базу, вопросы, индексы и секреты в ZIP-сабмит.

## Как работать со мной

- Отвечай по-русски.
- Объясняй, что и почему меняешь, а не только что сделал: код должен быть понятен без тебя.
- Если видишь ошибку в моём решении или более простой путь — скажи прямо, до того как начнёшь делать.
- Делай небольшие изменения, которые легко проверить и откатить. Перед крупной правкой предложи сделать коммит.
- Не добавляй фреймворки и зависимости (LangChain и т. п.) без обсуждения.
