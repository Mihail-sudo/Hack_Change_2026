# Контракт между частями системы

Версия: 0.2 (черновик до выхода кейса, 3 ноября 2026)
Любое изменение — сначала здесь, потом в коде, и с предупреждением в чате команды.

Этот файл описывает только **стыки** между частями: что одна часть передаёт другой. Как каждая часть устроена внутри, решает тот, кто её делает.

```
Виджет (Женя) ──HTTP──▶ API (Миша) ──вызов функции──▶ Агент (Елеазар) ──▶ LLM
                              │
                              └──▶ Telegram менеджеру (Миша)

cli.py (терминал) ──вызов функции──▶ Агент      ← та же функция, для разработки и тестов
```

## 1. Агент ↔ API

Агент — Python-пакет `agent`. API вызывает две функции и больше ничего не знает об устройстве агента.

### `respond` — ответ на сообщение клиента

```python
from agent import respond

result = respond(message: str, state: dict | None) -> AgentResult
```

**Вход:**
- `message` — текст последнего сообщения клиента, как он его ввёл.
- `state` — состояние диалога, которое агент вернул на прошлом шаге. Для нового диалога `None`.

**Выход `AgentResult`** (словарь):

| Поле | Тип | Что это |
|---|---|---|
| `reply` | `str` | Текст ответа клиенту. Показывается как есть. |
| `state` | `dict` | Новое состояние. API сохраняет его **целиком и без изменений** и передаёт на следующем шаге. |
| `actions` | `list[dict]` | Действия, которые должен выполнить API (см. ниже). Может быть пустым. |
| `done` | `bool` | `true`, если диалог завершён (лид передан или клиент попрощался). |

### `build_lead` — лид из формы контактов

```python
from agent import build_lead

lead = build_lead(state: dict | None, contact: dict) -> dict
```

Нужна для `POST /lead` (раздел 2): клиент оставил контакты в форме, а не в диалоге. API передаёт сохранённый `state` сессии (или `None`, если диалога не было) и контакты из формы, агент собирает лид по формату раздела 3 из того, что успел узнать.

Отдельная функция нужна, потому что API не читает `state` (правило ниже), а значит, сам не может достать оттуда слоты и историю.

### Правила

- `state` для API — «чёрный ящик». API не читает и не меняет его поля. Это даёт агенту право менять структуру состояния, не ломая API.
- `state` сериализуется в JSON: только строки, числа, bool, `null`, списки, словари.
- Агент не пишет в базу и не отправляет сообщения сам. Всё, что меняет внешний мир, он возвращает в `actions`, а выполняет вызывающий код: API на сервере или `cli.py` в терминале (там лид пишется в `leads/*.json`).
- Если агент упал с исключением, API отвечает клиенту запасной фразой (раздел 2) и пишет ошибку в лог. Сохранённое состояние при этом не перезаписывается.

### Действия (`actions`)

```json
{"type": "handoff", "lead": { ...объект лида, раздел 3... }}
```
Передать лид менеджеру: сохранить в базу и отправить в Telegram. Пока это единственный тип действия. Новые типы добавляются только через этот документ.

### Заглушки для разработки (пока агента нет)

```python
EXAMPLE_LEAD = {...}  # пример лида из раздела 3

def respond(message, state):
    state = state or {"turns": 0}
    state["turns"] += 1
    actions = [{"type": "handoff", "lead": EXAMPLE_LEAD}] if state["turns"] == 3 else []
    return {"reply": f"[заглушка] Вы написали: {message}", "state": state,
            "actions": actions, "done": state["turns"] == 3}

def build_lead(state, contact):
    return {**EXAMPLE_LEAD, "contact": {**EXAMPLE_LEAD["contact"], **contact}}
```
На третьем сообщении заглушка возвращает тестовый `handoff`, чтобы проверить отправку в Telegram.

## 2. Виджет ↔ API

Все запросы и ответы — JSON, кодировка UTF-8.

### `POST /chat`

Запрос:
```json
{
  "session_id": "строка, генерирует виджет (uuid4) и хранит до конца диалога",
  "message": "текст клиента"
}
```

Ответ `200`:
```json
{
  "reply": "текст ответа",
  "done": false
}
```

- `session_id` новый → API создаёт сессию и вызывает агента с `state = None`.
- Пустое сообщение или длиннее 2000 символов → `400` с `{"error": "..."}`.
- Ошибка агента или LLM → `200` с запасным ответом:
  `{"reply": "Извините, сейчас не получается ответить. Оставьте, пожалуйста, телефон, и менеджер свяжется с вами.", "done": false, "fallback": true}`.
  Виджет при `fallback: true` может сразу показать форму контактов.

### `POST /lead`

Запасной путь: клиент заполнил форму контактов в виджете, а не в диалоге.

Запрос:
```json
{
  "session_id": "тот же, что в чате (если диалог был)",
  "name": "", "company": "", "phone": "", "email": "",
  "consent_pd": true
}
```
- Нужно хотя бы одно из `phone` / `email`.
- `consent_pd` обязателен и должен быть `true`, иначе `400`.
- API вызывает `build_lead(state, contact)` (раздел 1) и выполняет передачу лида так же, как при `handoff`.

Ответ `200`: `{"ok": true}`

### `GET /health`
Ответ `200`: `{"ok": true}`. Нужен для Docker и чтобы перед защитой быстро проверить, что всё живо.

## 3. Лид (передаётся менеджеру)

Формат утверждает Виталий. Поля ниже — черновик.

```json
{
  "lead_id": "uuid",
  "created_at": "2026-11-09T15:30:00+03:00",
  "session_id": "...",
  "source": "chat",

  "contact": {
    "name": "Иван Петров",
    "company": "СНТ «Рассвет»",
    "role": "председатель правления",
    "phone": "+7 900 000-00-00",
    "email": null,
    "preferred_channel": "телефон"
  },
  "consent_pd": true,

  "segment": "snt",
  "problem": "неплательщики и подозрение на подключения в обход счётчиков",
  "slots": {
    "units": 120,
    "meters_installed": "да, на столбах",
    "meter_models": null
  },

  "recommended": [
    {"product_id": "askue_snt", "reason": "120 участков, проблема с неплательщиками и хищениями"}
  ],

  "summary": "3–5 предложений для менеджера: кто клиент, что болит, что предложено, о чём договорились.",
  "tags": ["АСКУЭ", "СНТ", "хищения"],
  "priority": "normal",

  "transcript": [
    {"role": "client", "text": "..."},
    {"role": "bot", "text": "..."}
  ]
}
```

**Правила:**
- `lead_id` и `created_at` заполняет API при сохранении. Агент может оставить их `null`.
- `source`: `"chat"` — лид собран в диалоге, `"form"` — из формы контактов.
- `contact`: обязательно хотя бы одно из `phone` / `email`. Остальные поля могут быть `null`.
- `consent_pd` всегда `true`. Без согласия лид не создаётся (152-ФЗ).
- `segment` — одно из значений таблицы ниже.
- `product_id` — только идентификаторы из таблицы ниже. Агент не придумывает продукты.
- `slots` — словарь, набор полей зависит от сегмента (`data/segments.yaml`). Чего клиент не говорил — `null`, а не догадка.
- `summary` пишет агент. Менеджер должен понять ситуацию, не открывая `transcript`.
- `priority`: `"normal"` или `"high"`. Правило, когда ставить `high`, определит Виталий.

### Сегменты клиентов (черновик, окончательный список — в `data/segments.yaml`)

| `segment` | Кто это |
|---|---|
| `energy_sales` | Энергосбытовая компания, гарантирующий поставщик |
| `grid` | Сетевая организация |
| `industry` | Производство, промышленное предприятие |
| `business` | Бизнес-центр, магазин, кафе, офис |
| `uk` | Управляющая компания, ТСЖ, ЖКХ |
| `snt` | СНТ, дачное товарищество |
| `vodokanal` | Водоканал, водо- и теплоснабжение |
| `other` | Не удалось определить |

### Продукты (из `data/services_kb.md`)

| `product_id` | Продукт |
|---|---|
| `askue_cloud` | Облачная платформа учёта (АСКУЭ, «Энергосфера в облаке МТС») |
| `askue_snt` | АСКУЭ для СНТ |
| `commercial_losses` | Поиск коммерческих потерь |
| `mining_detection` | Выявление майнинговых ферм |
| `vodokanal` | Цифровой водоканал |
| `meter_photo` | Распознавание показаний счётчиков по фото |
| `termokontur` | Термоконтур |
| `solar` | Солнечные электростанции под ключ |
| `orem` | Выход на оптовый рынок электроэнергии (ОРЭМ) |
| `hourly_metering` | Почасовой учёт для малых точек поставки (уточнить, входит ли в кейс) |

Если продукт добавляется или убирается — меняются и `data/services_kb.md`, и эта таблица.

## 4. Сообщение менеджеру в Telegram

Собирает API из лида. Пример:

```
🔔 Новый лид · СНТ
Иван Петров, председатель правления
СНТ «Рассвет»
📞 +7 900 000-00-00

Проблема: неплательщики, подозрение на подключения в обход счётчиков
Предложено: АСКУЭ для СНТ
Детали: 120 участков, счётчики на столбах

Резюме: ...
#АСКУЭ #СНТ #хищения
```
Название продукта берётся из таблицы продуктов (раздел 3) по `product_id`. Полный JSON лида хранится в базе, в Telegram — только этот текст.
