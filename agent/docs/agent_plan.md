# План разработки агента

План обновлён после первого чекпоинта и по материалам из `kimi_code_docs/`. Источники правды: официальная база с Google Drive, технический регламент сабмита и `docs/contract.md` для стыков команды.

Статусы: ⬜ не начат · 🟨 в работе · ✅ готово. Не отмечаем этап готовым без выполнения его критериев.

## Зафиксированные условия

- Официальная база: `data/knowledge-base/**/*.md`; материалы сайта больше не используются.
- Генеративная модель: `qwen/qwen3.8-27b`. Локально используется Polza, на платформе — API организаторов.
- Качество ответов на чекпоинте признано хорошим; изменения проверяем на регрессии.
- Целевое время ответа интерактивного агента — менее 8 секунд; текущий ориентир на чекпоинте — 5,2 секунды.
- Интерфейс одобрен без изменений. Новые функции интерфейса не планируем, нужна только корректная интеграция.
- Для автоматической проверки нужен пакетный `solution.py`: `questions.csv` → `submission.csv`. Это не интерактивный `cli.py`.
- На платформе нет своих ключей и данных в ZIP: API и входные файлы предоставляет окружение.

## ✅ Этап 7. Автоматический сабмит

- [x] `solution.py` читает `${DATA_DIR}/questions.csv` и создаёт `submission.csv` в рабочем каталоге.
- [x] Выход содержит ровно `id,answer`, все ID в исходном порядке, непустые ответы и стандартное CSV-экранирование.
- [x] Поддержаны переменные `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` и документированные альтернативы.
- [x] `TEMPERATURE`, `MAX_TOKENS`, `MAX_WORKERS` и `TOP_K` читаются из окружения при наличии.
- [x] ZIP содержит в корне только `solution.py`, корневые `.py`-модули и разрешённый `requirements.txt`; промпты генерируются в `prompts.py`.
- [x] `questions.csv`, `knowledge-base.zip`, индексы, секреты и файлы данных не включаются в ZIP.
- [x] Проверены формат результата, повторы ошибок и общий лимит 20 минут.
- [x] Сабмит использует отдельный режим прямых ответов без форм, слотов и диалоговых действий; интерактивный агент не затрагивается.
- [x] Добавлен гибридный поиск: лексика + BGE-m3 через RRF, с fallback на лексику. Локальный ключ Polza не имеет доступа к BGE, поэтому качество embeddings проверяется на платформе, а fallback проверен локально.

**Проверено:** локальная имитация платформы на плоском ZIP, две независимые заявки, переменные API и короткая история. Все 7 сценариев получили у судьи не менее 3/5, средняя оценка — 4,86/5, максимальное время ответа — 2,89 секунды.

**Готово, когда:** тестовый ZIP проходит локальную имитацию платформы до загрузки; учитываем лимит 5 сабмитов в день.
